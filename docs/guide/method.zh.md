# WLCR-SEA 如何生成预测

WLCR-SEA 分三步工作：

1. 根据明确的历史规律生成八个候选预测；
2. 排除依赖缺失数据的候选，再组合其余候选；
3. 进行一次幅度受限的最终修正。

通过这种设计，可以清楚查看每个未来小时、每项流量指标参考了哪些历史数据。

!!! tip "本页使用的四个术语"
    **专家**指一个候选预测；**掩码**标记历史数值是否存在；**路由器**为可用候选分配权重；**残差**是加权平均之后的最终修正。

## 第一步：生成八个候选预测

| 候选 | 通俗解释 | 何时可用 |
| --- | --- | --- |
| 前一天 | 前一天同一小时的值 | 该值存在 |
| 前一周 | 前一周同一小时的值 | 该值存在 |
| 前两周 | 前两周同一小时的值 | 该值存在 |
| 7 日同小时中位数 | 最多七个对应小时的中位数 | 至少存在一个对应值 |
| 14 日同小时中位数 | 最多十四个对应小时的中位数 | 至少存在一个对应值 |
| 周变化趋势 | 前周值加上幅度受限的周变化 | 前周和前两周的值都存在 |
| 输入中位数 | 当前 336 小时输入的中位数 | 该指标至少存在一个值 |
| 训练集先验 | 从训练集得到的典型值 | 模型已经完成训练 |

为了保持数组形状一致，程序内部可能会在缺失位置填入占位数。该位置能否参与计算由掩码决定，而不是由占位数决定。移除数据后，所有汇总类候选都会重新计算，因此被删除的数值不会继续影响预测。

## 第二步：排除不可用候选并组合其余候选

针对每个未来小时和指标，模型先保留能够实际计算的候选，再为它们分配总和为 1 的权重。依赖缺失历史数据的候选，其权重严格为零。

从技术上看，所选模型会针对每个预测时刻，在压缩后的可用候选列表上应用 **Entmax**，再把得到的权重映射回原来的八个位置。Entmax 可以把部分权重精确设为零，因此本实现不需要用“非常小的负数”近似隐藏不可用候选。

模型还会读取候选的可靠度，例如计算某个中位数时使用了多少个观测值。可靠度可以影响权重，但不能让原本不可用的候选变为可用。

## 第三步：限制最终修正幅度

候选的加权平均值构成对数空间中的主要预测，模型随后可以加入一个学习得到的修正值。该修正先经过 `tanh`，再乘以固定上限，因此不会无限增大。最终预测位于：

\[
\left[\min_{j \in A} e_j - b,\; \max_{j \in A} e_j + b\right]
\]

其中 \(A\) 是可用候选集合，\(b\) 是最大修正幅度。通俗地说，最终结果不会大幅超出当前可用历史候选所支持的范围。

## 可以保存哪些检查信息

计算记录可以保存输入哈希、模型版本、候选值、可用性、可靠度、权重、加权平均值、最终修正、预测结果和范围检查。仓库测试还会验证模型输入只能包含允许的字段，防止模型悄然加入按小区查询的额外数据。

!!! info "公开 Demo 使用哪个模型"
    Space 运行较简单的 `A0_fixed` 基线：前一周 0.7、前两周 0.2、7 日同小时中位数 0.1。某个候选不可用时，其余权重会按比例调整，使总和保持为 1。由于训练后的 A6 检查点尚未公开，Demo 输出并非论文训练模型的预测结果。
