# 方法

WLCR-SEA 分三步：

1. 生成八个历史候选；
2. 排除不可用候选，为其余候选加权；
3. 进行受限修正。

保存的候选和权重说明每项预测受哪些历史数据影响。

!!! tip "术语"
    **专家：**候选。**掩码：**存在/缺失标记。**路由器：**加权步骤。**残差：**最终修正。

## 1. 候选

| 候选 | 通俗解释 | 何时可用 |
| --- | --- | --- |
| 前一天 | 前一天同一小时的值 | 该值存在 |
| 前一周 | 前一周同一小时的值 | 该值存在 |
| 前两周 | 前两周同一小时的值 | 该值存在 |
| 7 日同小时中位数 | 最多七个对应小时的中位数 | 至少存在一个对应值 |
| 14 日同小时中位数 | 最多十四个对应小时的中位数 | 至少存在一个对应值 |
| 周变化趋势 | 前周值加上幅度受限的周变化 | 前周和前两周的值都存在 |
| 输入中位数 | 当前 336 小时输入的中位数 | 该指标至少存在一个值 |
| 训练集先验 | 从训练集得到的典型值 | 模型已经完成训练 |

缺失位置可以有占位数，但是否可用由掩码决定。删除数据后，汇总候选会重新计算，已删除数值不会进入预测。

## 2. 路由

对每个小时和指标，可用候选的权重之和为 1，不可用候选的权重为 0。

模型只在压缩后的可用列表上应用 **Entmax**，再恢复八个位置。不需要用极小负数近似遮蔽候选。

可靠度（如中位数的样本数）可以改变权重，但不能恢复不可用候选。

## 3. 受限修正

候选的加权平均值是对数空间中的主要预测。学习得到的修正经过 `tanh` 和固定上限，最终结果位于：

\[
\left[\min_{j \in A} e_j - b,\; \max_{j \in A} e_j + b\right]
\]

其中 \(A\) 是可用候选集合，\(b\) 是修正上限。结果不会大幅超出可用候选的范围。

## 计算记录

记录可包含输入哈希、模型版本、候选、可用性、可靠度、权重、平均值、修正、预测和范围检查。测试还会拒绝未批准的输入字段。
