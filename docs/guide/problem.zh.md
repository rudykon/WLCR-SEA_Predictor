# 请求局部服务问题

WLCR-SEA 从一项运营约束出发：在线评分器只能读取当前请求所对应小区的实时流量。
前端可以使用身份完成授权与请求组装，但预测器不会把该身份作为特征，也不会用它发起其他查询。

## 密封请求

每个请求包含一个有序张量和具有最终权威性的观测掩码：

- 连续 336 个历史小时；
- 四个流量指标；
- 观测值使用 `log1p` 变换；
- 每个小时、每个指标都有布尔观测状态；
- 小区身份不会作为特征传给预测函数。

预测目标是同四个序列的未来 24 小时。

## 在线路径可以使用什么

| 可以使用 | 评分器不可使用 |
| --- | --- |
| 当前请求的数值与掩码 | 其他小区的实时流量 |
| 冻结训练统计量 | 按小区查询的元数据文件 |
| 单个版本化全局检查点 | 拓扑或邻区表 |
| 固定方法配置 | 外部特征库 |
| 模型外用于审计的不透明 ID | 跨请求流量缓存 |

## 为什么这项约束会改变模型

当邻区状态经过授权时，图模型或邻区感知模型可能很有价值，但它们解决的并不是同一问题。
WLCR-SEA 转而把当前请求压缩成有限个季节候选，使预测能够从同一输入重新播放。

!!! note "请求局部意味着什么，又不意味着什么"
    请求局部描述的是在线证据路径。它不会自动提供匿名化、加密、访问控制、差分隐私，
    也不能阻止服务系统其他环节发生信息泄漏。
