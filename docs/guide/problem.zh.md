# 从午夜请求到可审计预测

WLCR-SEA 从一个现实问题出发：**当预测服务只能读取当前请求所对应小区的实时流量时，
如何帮助运营方规划第二天？** 在遥测不完整时，答案仍应可用；事后重放时，也不能暗中依赖其他小区的数据。

## 背景：为什么会产生这次请求

短期蜂窝流量预测可以为主动无线资源与服务容量规划提供支持。规划系统可能希望提前了解未来 24 小时内，
上行激活用户、下行激活用户、下行已用 PRB 和上行已用 PRB 的预期变化形态。

本研究刻意设置了一个受限的预测环境：身份感知入口可以授权目标小区并组装数据，
但评分过程不能再查询邻近小区的实时流量、拓扑服务或跨请求缓存。
这种职责分离适用于隔离的边缘域：访问约束、故障隔离与事后重放共同要求在线证据面足够小且明确。

## 什么情况下应选择其他问题形式

WLCR-SEA 不应被视为所有蜂窝预测任务的默认答案。

- 如果经过授权的邻区流量和拓扑信息在评分时稳定可用且十分重要，图模型或多小区模型面对的是更丰富的信息集。
- 如果突发事件、天气、移动性、扩容变化或日历效应占主导，手工定义的季节专家库可能无法捕捉，除非显式引入并重新验证这些信号。
- 如果应用要求经过校准的预测不确定性，路由熵不能替代它；本研究没有发现熵与误差之间存在有用相关性。
- 如果预测将驱动自动控制，仅凭当前预测证据不足以支撑部署，还需要前瞻性的系统安全与影响验证。

## 密封请求

每个请求包含一个有序张量和具有最终权威性的观测掩码：

- 连续 336 个历史小时；
- 四个流量指标；
- 观测值使用 `log1p` 变换；
- 每个小时、每个指标都有布尔观测状态；
- 小区身份不会作为特征传给预测函数。

预测目标是同四个序列的未来 24 小时。

## 在线路径可以使用什么

| 可以使用 | 评分器不可使用 |
| --- | --- |
| 当前请求的数值与掩码 | 其他小区的实时流量 |
| 冻结训练统计量 | 按小区查询的元数据文件 |
| 单个版本化全局检查点 | 拓扑或邻区表 |
| 固定方法配置 | 外部特征库 |
| 模型外用于审计的不透明 ID | 跨请求流量缓存 |

## 为什么这项约束会改变模型

黑箱预测器可以在不公开参考依据的情况下给出点估计。WLCR-SEA 则把当前请求压缩成有限个具名季节候选，
使它们能够从同一输入重新构造。可用性是结构性的，路由只作用于仍然存在的证据，修正则被限制在路由基线周围。

!!! note "请求局部意味着什么，又不意味着什么"
    请求局部描述的是在线证据路径。它不会自动提供匿名化、加密、访问控制、差分隐私，
    也不能阻止服务系统其他环节发生信息泄漏。
