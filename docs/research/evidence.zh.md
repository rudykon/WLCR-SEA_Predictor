# 实验结果

WLCR-SEA 并不是所有情况下都最准确的模型。历史完整时 DLinear 更好；在研究设定的
严重遥测缺失对比中 WLCR-SEA 更强，并导出便于复核的路由记录。若要回放，还需要
原始请求以及固定的源码和模型版本。

!!! info "指标口径"
    WAPE 越低越好。下文每个 WAPE 都明确标注聚合方式。配对置信区间包含 0，表示
    差异不明确。

## 评估设置

| 项目 | 评估设置 |
| --- | --- |
| 数据 | 一个匿名地区的 736 个小区、527,760 个小区小时 |
| 请求 | 单个小区，336 小时历史，四项指标，观测掩码 |
| 目标 | 同一小区未来 24 小时的四项指标 |
| 主模型 | WLCR-SEA 五模型集成，种子 42–46，在原始流量空间平均 |
| 完整历史测试 | 研究预先定义的固定后续时间段 |
| 缺失测试 | 所有对比模型移除完全相同的历史位置 |

[固定版本的公开模型仓库](https://huggingface.co/config-h/WLCR-SEA-Predictor/tree/eb4447f4ebab8f9caa003d92c838ed8e750963bd)报告该集成在
完整历史下的**宏小区 WAPE 为 0.177612**、**池化 WAPE 为 0.184915**、
**四指标宏平均 WAPE 为 0.195511**。它们是同一评估流程的不同聚合方式，不能混用。

评估中的压力测试按连续区块、最近时段或指标异步方式移除数据。请求移除 50% 时：

| 缺失模式 | WLCR-SEA 四指标宏平均 WAPE |
| --- | ---: |
| 连续区块 | 0.2196 |
| 最近尾部 | 0.2460 |
| 指标异步 | 0.2172 |

在与 DLinear-Aug、PatchTST-Aug、GRU-D 的 **9 项预设严重缺失对比**中，
WLCR-SEA 的四指标宏平均 WAPE 均更低。部分中等缺失率下，与 DLinear-Aug 和
PatchTST-Aug 的配对区间仍包含 0。

**结论**：优势只适用于已测试的缺失模式、缺失率、数据和本次训练结果，不代表任意故障。

不确定性分数。

## CPU 成本与小区不重叠审计

单 CPU 线程、batch=1、逐请求运行时：

| --- | ---: | ---: | ---: |
| 单个 WLCR-SEA 模型 | 6.802 ms | 7.574 ms | 16.2 KiB |
| 五模型集成 | 34.705 ms | 38.684 ms | 148.8 KiB |

训练和测试使用不同小区时，WLCR-SEA 的**四指标宏平均 WAPE 为 0.1967**。它与
DLinear-Aug、先前方法的差异仍不明确，优于 PatchTST-Aug。所有小区仍来自同一地区。

## 适用边界 { #limitations }

- **数据与泛化**：一个匿名地区、约一个月；所有预测从午夜开始；后续时段数据影响过
  部分设计选择；小区不重叠审计仍在同一地区内。
- **准确性**：完整历史下 DLinear 更好；中等缺失率的优势并不总是明确；测试模式无法
  覆盖全部遥测故障。
- **不确定性**：路由熵和专家权重都不是经过校准的不确定性估计。
- **隐私与服务**：请求内计算不提供访问控制、加密、匿名化、差分隐私、安全日志或
  留存策略；生产系统需要单独实现这些能力。
- **运营范围**：研究评估预测，不评估网络控制动作、调度决策或业务收益。

本项目适合研究和受控评估。投入运营前必须重新验证模型、数据契约、安全控制和故障模式。
